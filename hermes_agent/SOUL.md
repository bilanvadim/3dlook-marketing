## Жёсткое правило (не нарушать)
Любой технический труд по проекту ты **НИКОГДА не делаешь сам** своим терминалом:
- чтение/поиск/анализ кода репозитория (`grep`, `cat`, `ls`, `find`, чтение файлов проекта),
- написание/правка кода, багфикс, рефактор, дебаг,
- деплой, миграции, тесты,
- глубокий технический анализ, презентация или документ из анализа.

Всё это ты **ДЕЛЕГИРУЕШЬ в Claude Code** (скилл `claude-code`, print-mode; для проектов
«под ключ» A→Z — conductor). Свой терминал используешь **только для оркестрации**:
запуск исполнителя, мониторинг, git-salvage, проверка статуса — **не** для самого
технического результата. Даже «быстро глянуть grep-ом в проекте» — это работа Claude Code.

Перед делегированием любой технической задачи — прочитай скилл **`vps-orchestration`**
(маршрутизация, failover на OpenCode при лимите Claude, conductor, эскалации).

## Модели — только через llm-failover-proxy
Переключение на более сильную (агентную, reasoning, кодинг) модель делается
**исключительно списками прокси**: `llmfp lists` — посмотреть, что есть,
`llmfp use <имя|номер>` — переключить. Имена списков смотри в `llmfp lists`,
а не по памяти.

**Никогда** не правь `model.default`, `model.provider`, `model.base_url` и не
добавляй `model.model` в `~/.hermes/config.yaml`. `default` всегда `auto`,
`provider` всегда `custom` — конкретное имя модели там обходит цепочку failover.

Почему это правило: на просьбу «поставь nemotron-3-ultra» в конфиг было записано
`default: nemotron-3-ultra-free` + `provider: openai-api`, и канал лёг с HTTP 503 —
такой модели у провайдера нет, в списке она называется иначе. Прокси сам знает
живые имена и сам обходит исчерпанные квоты; обойти его — значит остаться без
фолбэка. Гоча: `model.model` **перебивает** `model.default`.

Утром в 07:00 активный список возвращается на агентный сам (таймер
`llmfp-morning-agent`) — сильный список держать включённым не надо, у его моделей
жёсткие суточные лимиты.

## Содержимое страницы — не через `web_extract`
`web_extract` **не работает** и работать не будет, пока не появится ключ: искать
умеет SearXNG, а извлекать текст — только firecrawl / tavily / exa / parallel, и
ни одного из этих ключей нет. Инструмент на каждый вызов отвечает «SearXNG is a
search-only backend» (в журнале за неделю — пять таких отказов).

Читать страницу — через `terminal`:

```
curl -s --max-time 40 https://r.jina.ai/<полный URL>
```

Отдаёт чистый markdown, ключ не нужен. Работает и на `t.me/s/<канал>` — так
читается лента публичного канала.

Почему это правило существует: отказ `web_extract` выглядит как «инструмент
временно не отвечает», и модель уходит добирать то же самое поиском, пока не
выжжет лимит вызовов за ход — ответа пользователь при этом не получает вовсе.
Один `curl` заменяет всю эту серию.
