# Model Router — «Модели дня» (только бесплатные) и утренний отчёт

Каждое утро в 07:00 роутер выбирает **четыре** вещи и шлёт отчёт в Telegram.
Процесс полностью детерминированный: 0 LLM-запросов «на подумать», только
API-листинг + $0-пробы бесплатных моделей.

> Файлы: `agents-ai/telegram-bot-agent/hermes-agent/ops/model-router/` → копируются в `~/.hermes/model-router/`.
> Запуск: systemd timer `model-router-refresh.timer` (07:00, ±120с random delay).
> Ручной прогон без записи: `python3 ~/.hermes/model-router/refresh.py --dry-run`.

## Четыре выбора, и почему они разные

| Что | Откуда выбирается | Требование | Куда пишется | Сегодня (08.08.2026) |
|---|---|---|---|---|
| **Рабочая модель Hermes** | только бесплатные **OpenCode Zen** | **самая сильная живая**; картинки НЕ требуются | `config.yaml` → `model.default` + `model.provider: opencode-zen` | `nemotron-3-ultra-free` (сила 82, text-only) |
| **Читатель картинок** | только бесплатные OpenCode Zen | **доказал, что видит** (red-square проба) | `config.yaml` → `auxiliary.vision` + `pick.json.best_vision` | `mimo-v2.5-free` (сила 62) |
| **Fallback Hermes** | только бесплатные OpenCode Zen | следующая живая по силе | `config.yaml` → `fallback_providers[0]` | `deepseek-v4-flash-free` |
| **Запасной кодинг-агент** (OpenCode CLI) | **топ-3 первых** провайдера таблицы `PERMANENT_FREE` в [awesome-freellm-apis](https://github.com/open-free-llm-api/awesome-freellm-apis) | лимитов хватает + самая сильная, победитель по **скорости**, подтверждён живым прогоном OpenCode | `opencode.jsonc` (`model`+`small_model`) + ключ в `auth.json` | топ-3 на 08.08: NVIDIA NIM · ModelScope · Cloudflare Workers AI |

**Смена курса (08.08.2026): vision больше не гейт на рабочей модели.** Раньше
Hermes обязан был весь день носить модель, умеющую видеть, — и платил за это
мозгами: 62 против 82 у сильнейшей текстовой. Теперь читатель **берётся напрокат
на один ход** — тот, в котором пришла картинка, — и сразу возвращается назад
(`ops/vision-switch/`, там же полное описание). Скриншоты читаются той же
сильнейшей видящей моделью, что и раньше, а всё остальное время работает
сильнейшая модель вообще.

Почему выборы всё равно раздельные: у читателя и у кодера разные требования
(доказанное зрение против измеренной скорости), и кодер ищется шире, чем Zen.

## Выбор модели для запасного кодинг-агента (топ-3 бесплатных провайдера)

Источник (с 08.08.2026) — **[open-free-llm-api/awesome-freellm-apis](https://github.com/open-free-llm-api/awesome-freellm-apis)**.
Прежний `cheahjs/free-llm-api-resources` начал отдавать **404** (README удалён), и
роутер несколько дней молча откатывался на Zen — смена источника это чинит.

Берётся **только таблица `PERMANENT_FREE`** (постоянно бесплатный тир). Таблица
`RENEWABLE` (возобновляемые кредиты) в ротацию не попадает никогда — по тому же
правилу, по которому не попадал раздел с триальными кредитами у cheahjs. ⚠️ Там
теперь живёт **OpenRouter**, то есть из ротации он выбыл.

Оценивается `TOP_N_PROVIDERS = 3` **первых строки таблицы** — и только они, даже
если ключ есть у провайдера ниже (правило Сергея от 08.08.2026; до этого
проверялись все провайдеры с ключами). На 08.08.2026 это NVIDIA NIM (123 модели),
ModelScope (55), Cloudflare Workers AI (39) — ключи есть у всех трёх.

### Гочи каждого из троих

| Провайдер | Что не очевидно |
|---|---|
| **NVIDIA NIM** | Сильнейшие модели (`glm-5.2`, `deepseek-v4-pro`) **не укладываются в таймаут 190 с** — проба их стабильно теряет. Реально выигрывает что-то среднее и медленное (7 tok/s на замере 08.08). |
| **ModelScope** | `/v1/models` отвечает **200 даже без валидного токена** — «каталог загрузился» ничего не доказывает. Генерация до **привязки аккаунта Alibaba Cloud** отдаёт 401. Хост `.cn` про причину врёт («valid token»), `.ai` — говорит правду, поэтому в `PROVIDERS` прописан **`.ai`**. |
| **Cloudflare Workers AI** | Три отдельные ловушки: (1) `GET /ai/v1/models` → **405**, каталог берётся из нативного `ai/models/search`; (2) в каталоге **не помечено**, что входит в бесплатный план — топовые модели отдают мгновенный 403 «not available on the Workers Free plan», поэтому такие пропуски **не тратят попытки** (иначе провайдер выглядит мёртвым, съев все три на моделях, звонить которым не имел права); (3) base URL содержит **account_id**, он подставляется `ensure_base()` и пишется в `opencode.jsonc` явным `provider.options.baseURL` — иначе CLI попытается интерполировать переменную окружения, которой у systemd-юнита нет. |

Ещё гоча, общая: тело ошибки у провайдеров разной формы — у OpenAI-подобных
`{"error":{"message":…}}`, у Cloudflare `{"errors":[{"message":…}]}` (**множественное
число и список**). Парсер читал только первую форму, из-за чего текст Cloudflare
терялся целиком и оставалось голое `HTTP 403` — а вместе с текстом терялась и
фраза, по которой распознаются платные модели. Разбирает обе формы `_error_message()`.

⚠️ **Порядок в новом репо — по числу бесплатных моделей, а не по щедрости
лимитов**, как сортировал cheahjs. «Топ-3» теперь значит «самый широкий каталог».

Парсится по HTML-маркерам (`<!-- BEGIN_PERMANENT_FREE -->` и т.д.) — их пишет
генератор репозитория, поэтому они стабильнее, чем заголовки с эмодзи. Помимо
списка провайдеров оттуда берутся ещё две таблицы: `QUICK_REF` (base URL) и
`BEST_MODELS` (до трёх id моделей с их **персональными** лимитами — именно из них
собирается `limits`, потому что провайдерского `**Limits:**` в прозе больше нет).

Полный список моделей всё равно берётся из **собственного OpenAI-совместимого
`/models`** каждого провайдера: в репо только три лучших. Зато id там теперь
настоящие (`gemini-3.6-flash`), а не человеческие имена, так что сопоставлять их с
живыми проще, чем раньше.

Порядок выбора внутри провайдера:

1. Отсеять не-кодинговые модели (tts / image / audio / robotics / embed / guard) —
   иначе они выигрывают по размеру, не умея писать код.
2. **Лимитов должно хватать.** `MIN_RPD = 100` запросов/сутки: кодинг-агент тратит
   много запросов на одну задачу, поэтому модель с 20/сутки бесполезна, какой бы
   сильной ни была. Реальный пример: `gemini-3.6-flash` (сила 84) — 20 запросов в
   сутки, а `gemini-3.5-flash-lite` (сила 72) — 500 и вдвое быстрее.
3. Из тех, у кого лимиты рабочие, — **самая сильная**. Сила берётся в таком
   приоритете: опубликованный `benchmarks.artificial_analysis.coding_index`
   (есть только у OpenRouter) → `model-strength.json` → эвристика по числу
   параметров из id. ⚠️ Шкалы `coding_index` (~20-60) и таблицы сил (~55-90)
   **несравнимы**: если хоть у одной модели есть benchmark, соревнуются только
   такие (см. `_rank`) — иначе победила бы та, у которой benchmark просто
   отсутствует.

Затем **одна и та же задача на кодинг** («один HTML-файл: форма ровно из 10
подписанных полей + кнопка») уходит выбранной модели каждого провайдера, и
замеряется время.

### Победитель — по КАЧЕСТВУ, а не по одной сегодняшней скорости

Одно измерение у нестабильного провайдера — это замер его очереди, а не модели.
Наши замеры за один день: `openrouter/nemotron-3-ultra` дал **14.5 → 80.6 tok/s**
(разброс 54 %, десять проб), а `google/gemini-3.5-flash-lite` — 357 → 459 (7 %,
двенадцать проб). Выбор по максимуму или по одному замеру раз за разом коронует
того, у кого в тот момент была пустая очередь.

```
оценка = p25(tok/s) × success_rate × (1 − min(CV, 0.5))
```

| Множитель | Зачем |
|---|---|
| **p25**, не среднее | агент делает десятки ходов и живёт в плохом хвосте, а не в лучшем случае. `nemotron-3-ultra` по p25 — 16 tok/s, а не 80 |
| **success_rate** | модель, отвечающая через раз, бесполезна при любой скорости (`glm-5.2` дописал форму в 1–2 попытках из 4). Считается по ВСЕМ пробам — поэтому в историю пишутся и провалы |
| **штраф за CV** | 400 ± 20 лучше, чем 500 ± 300. Проверено на синтетике: стабильная 400 (оценка 392) обходит рваную с медианой 800 (оценка 60) |

Порог надёжности — `MIN_SUCCESS_RATE` (0.6). Модель, которую видели впервые,
получает сегодняшнюю скорость со скидкой `NEW_MODEL_DISCOUNT` (0.7): один замер
весит меньше накопленной репутации, но новичок всё равно может победить — просто
должен победить явно.

### Гистерезис — не менять работающего ради шума

Действующий кодер сохраняет место, пока не сломался или пока претендент не лучше в
**`HYSTERESIS` = 1.3 раза** по этой оценке. Без этого выбор гуляет между
провайдерами на случайных флуктуациях — наблюдали, как он прыгал Google↔Zen на
прогонах с разницей в минуты.

Метрика набирает силу по мере накопления: при `n < 2` работает скидочный режим,
осмысленные p25/CV появляются после ~5 замеров на модель (то есть через несколько
дней ротации).

Две ловушки замера, из-за которых хороший провайдер выглядел бы «тормозящим»:

- **tok/s считается по ВСЕМ сгенерированным токенам** (`total − prompt`), а не по
  `completion_tokens`. Reasoning-модели списывают почти всю генерацию в скрытое
  размышление: `gemini-3.6-flash` отдал 43 «видимых» токена на 1228-токенный ход —
  это читается как 6 tok/s, тогда как правда ~190.
- **`max_tokens` = 4000.** При 1200 та же модель истратила весь бюджет на
  размышление и вернула форму, обрезанную посреди тега, — негодный образец.

Плюс ответ **валидируется**: должно быть ≥8 `<input>` и не `finish_reason=length`,
иначе модель, которая быстро отвечает мусором, победила бы в гонке скорости.
Таймаут пробы — **90 с** (ответ дольше полутора минут для запасного кодера всё
равно негоден); худший случай прогона — 3 провайдера × 3 кандидата × 90 с, у
oneshot-юнита `TimeoutStartUSec=infinity`, так что systemd его не оборвёт.

**Изоляция провайдеров.** У каждого провайдера свой `try`: раньше весь блок сидел в
одном, и единственная ошибка (те самые перцентили) выбрасывала замеры ВСЕХ трёх и
молча откатывала на Zen. Плюс прогон печатает пошаговый лог с `flush` — отчёт
уходит одним `print` в конце, поэтому падение в середине не оставляло следов; в
journal утреннего запуска теперь видно каждую пробу.

**Сравнение с заявленной скоростью.** Из троих её публикует только OpenRouter —
`throughput_last_30m` / `latency_last_30m` в `/models/{slug}/endpoints`. ⚠️ **Без
ключа эти поля приходят `null`, а с ключом — перцентильными словарями**
(`{"p50": 34, "p75": 48, "p90": 65, "p99": 139}`). На этом код и упал в первый же
день с реальным ключом (`max()` по словарям → `TypeError`), поэтому разбор идёт
через `_p50()`, а эталон — **медиана p50 по endpoint-ам**, не максимум: маршрут
выбирает OpenRouter, и обещать самый быстрый endpoint значит каждое утро объявлять
обычный прогон медленным.

Для остальных эталон — **наш собственный лучший замер** из `coder-history.json`
(14 дней). Если сегодняшний tok/s ниже 60% эталона, в отчёт идёт «медленнее
обычного — похоже на наплыв».

| Провайдер | Модель | Сила | Лимит | Время | tok/s | Вердикт |
|---|---|---|---|---|---|---|
| OpenRouter | `nvidia/nemotron-3-ultra-550b-a55b:free` | 49.3 (`coding_index`) | 50/сутки | 95 с | 14.5 | заявлено ~53 p50 → **наплыв** |
| **Google AI Studio** | **`gemini-3.5-flash-lite`** | 72 | **500/сутки** | **3.0 с** | **375** | ✅ выбран |
| NVIDIA NIM | `meta/llama-3.2-90b-vision-instruct` | 85 (эвристика ~90B) | не заявлен | 44 с | 8.8 | ок |

Сильнейшие модели NVIDIA (`z-ai/glm-5.2`, `deepseek-ai/deepseek-v4-pro`) **обе
упёрлись в таймаут 90 с** — для этого и нужен спуск по списку (до 3 кандидатов на
провайдера).

**Вывод, который стоит помнить:** у бесплатных провайдеров «самая сильная» и
«пригодная для работы» — почти всегда разные модели. Гигант на 550B выдаёт 14 tok/s
при 50 запросах в сутки, а Flash-Lite — 375 tok/s при 500. Поэтому финальное
решение принимается **по скорости**, иначе роутер каждое утро выбирал бы
неработоспособного гиганта. По той же причине тяжёлый режим Hermes (`/heavy`)
берёт этого же победителя, а не формально сильнейшую модель: 8.8 tok/s означает
несколько минут на один ответ в Telegram.

**Нет ключа → бот просит.** Ключи ищутся в `~/.hermes/ai-models.env` (создаётся
сам, 0600), затем в `~/.hermes/.env`, по всем алиасам имён из models.dev — поэтому
ключ Google находится в уже существующем `OPENAI_API_KEY`. Если ключа нет, провайдер
пропускается, а в Telegram уходит просьба: ссылка на регистрацию + имя переменной.
Победитель прописывается в `auth.json` OpenCode, так что агент работает независимо
от того, кто его запускает.

> Ключ через один OpenCode не годится: zen-ключ покрывает только zen-модели. Но
> OpenCode нативно знает `openrouter` / `google` / `nvidia` (каталог models.dev), так
> что достаточно своего ключа на провайдера — кастомные endpoint'ы и прокси не нужны.

## Пошагово, что делает `refresh.py`

```
07:00 → timer → refresh.py
  │
  ├─ 1. model-strength.json (силы моделей + ctx_bonus)
  ├─ 2. Zen /models → живые модели
  ├─ 3. models.dev/api.json → cost / context / modalities (кеш cache/modelsdev.json)
  │
  ├─ 4. Бесплатные = живые ∩ (catalog cost.input == 0)
  ├─ 5. Ранжировать: score = strength + ctx_bonus×(context ≥ ctx_big)
  │     (cost больше не штрафуется — он у всех 0)
  │
  ├─ 6. Один проход по рейтингу сверху, закрывающий три роли сразу:
  │       рабочая     = первая, которая ОТВЕЧАЕТ (free_ok). Зрение не требуется.
  │       fallback    = следующая отвечающая.
  │       читатель    = первая, которая ДОКАЗАЛА зрение:
  │                     claims_vision (каталог) → free_ok() → vision_ok() назвала цвет
  │     Картинкой пробуются только заявившие vision. Как только все три роли
  │     закрыты — пробы прекращаются, остальные идут в отчёт помеченными.
  │
  ├─ 7. Читатель → config.yaml `auxiliary.vision` (+ pick.json.best_vision,
  │     откуда его берёт ops/vision-switch для переключения на один ход)
  │
  ├─ 8. КОДЕР: cheahjs-репо → топ-3 бесплатных провайдера → ключи из
  │     ai-models.env/.env → по одной сильнейшей модели с рабочими лимитами у
  │     каждого → одинаковая кодинг-проба → победитель по tok/s → auth.json
  │     (нет ключа → просьба Сергею в Telegram). Zen — сеть безопасности.
  │
  ├─ 9. Записать: config.yaml (default+provider, fallback_providers),
  │              opencode.jsonc (model+small_model), pick.json
  ├─ 10. Перезапустить gateway — ТОЛЬКО если выбор изменился
  └─ 11. Telegram-отчёт со всем бесплатным раскладом
```

Правило «лучше вчерашнее рабочее, чем свежее сломанное» действует **по каждой
роли отдельно**:

- **ни одна модель не отвечает** → `config.yaml` не трогается вообще, работает
  вчерашняя рабочая, в отчёт уходит 🚨;
- **никто не подтвердил vision** → не трогается `auxiliary.vision` (остаётся
  вчерашний читатель), рабочая при этом обновляется нормально. `vision-switch`
  сам проверит, жив ли читатель, а если нет — ход просто пройдёт без него.

## Vision-проба (`vision_ok`) — почему не верим каталогу

Флаги `modalities.input` / `attachment` в models.dev — самоописание провайдера и
бывают устаревшими (тот же каталог держит закончившиеся промо как «free»).
Поэтому vision проверяется вопросом к модели: ей показывают **PNG 8×8 чистого
красного** (100 символов base64, вшито в `router_lib.RED_PNG_B64`) и просят
назвать цвет одним словом. Проходит только та, что реально называет красный
(`red` / `красн` / `红` / `rouge` / `rot`).

Две гочи, из-за которых проба врёт, если их не учесть:

- **`max_tokens` должен быть большим (300).** Reasoning-модели тратят первые ~25
  токенов на размышление и при `max_tokens=20` возвращают **пустой `content`** —
  рабочая vision-модель выглядит сломанной. (Реальный случай: `mimo-v2.5-free`
  при 20 → пусто, при 300 → «Red».)
- **Text-only модель отвечает на картинку HTTP 400.** Это нормальный ответ «я
  принимаю только текст», поэтому такие модели вообще не пробуются картинкой —
  их отсекает флаг каталога, иначе каждое утро уходила бы минута на
  гарантированные отказы.

## Запасной кодинг-агент (OpenCode CLI) — три обязательных условия

Роутер пишет `~/.config/opencode/opencode.jsonc`. Без каждого из трёх пунктов
`opencode run` **молча** выходит с кодом 0 и не печатает ничего:

1. **Креды провайдера `opencode`** в `~/.local/share/opencode/auth.json`
   (`{"opencode": {"type": "api", "key": "<OPENCODE_ZEN_API_KEY>"}}`). CLI по
   умолчанию авторизован только для `opencode-go`.
2. **`small_model` тоже должен быть бесплатным.** OpenCode перед каждым запуском
   генерирует заголовок сессии своей встроенной «маленькой» моделью
   `gpt-5-nano` — она **платная** на zen. При нулевом балансе этот вызов даёт
   `401 CreditsError`, стрим падает, вывода нет. Роутер ставит `small_model` = та
   же бесплатная модель.

## model-strength.json — настройка

```
score = strength + ctx_bonus × (context ≥ ctx_big)
```

| Ключ | Значение | Смысл |
|---|---|---|
| `default_strength` | 60 | сила неизвестной модели |
| `ctx_bonus` | 4.0 | бонус за context ≥ `ctx_big` |
| `ctx_big` | 1 000 000 | порог «большого» контекста |
| `cost_weight` | 3.0 | **не используется** (все модели бесплатные), оставлен для истории |
| `strength` | таблица | ручные оценки 0-100 по классу/размеру модели |

Бесплатный ассортимент на Zen ротируется (промо приходят и заканчиваются),
поэтому в `strength` держим строки и для free-моделей — иначе все они получают
`default_strength=60` и «самая мощная» становится случайной.

## router_lib.py — хелперы

| Функция | Что делает |
|---|---|
| `env(key)` / `zen_key()` | ключ из `~/.hermes/.env`; `zen_key` = ZEN, иначе GO (legacy) |
| `get_json(url, key)` | GET с Bearer + UA `curl/8.5.0` (Cloudflare блокит python-urllib UA) |
| `load_catalog()` | models.dev/api.json + кеш `cache/modelsdev.json` |
| `free_ok(key, model)` | модель РЕАЛЬНО отвечает ($0 ping) — ловит закончившиеся промо |
| `vision_ok(key, model)` | red-square проба → `{ok, ms, answer, error}` |
| `probe_go(key, base, model)` | legacy health-probe подписки Go |
| `telegram(text)` | HTML-сообщение в Telegram |
| `restart_gateway()` | `systemctl --user restart hermes-gateway.service` |
| `set_model_default(model, provider)` | `model.default` **и** `model.provider` в config.yaml |
| `set_auxiliary_vision(model, provider)` | две строки внутри `auxiliary.vision`, **построчно**: соседний `approval:` трогать нельзя (черновик, переписывавший блок целиком, молча сносил судью одобрений) |
| `set_fallback(model, provider)` | блок `fallback_providers` в config.yaml |
| `set_opencode_model(model, provider)` | `opencode.jsonc` кодинг-агента (`model` + `small_model`) |
| `set_opencode_auth(provider_id, key)` | ключ провайдера в `auth.json` OpenCode (0600) |

> ⚠️ **2026-07-11:** `set_fallback()` резал старый блок построчно по отступу, а
> YAML разрешает элементы списка без отступа (`fallback_providers:\n- provider: x`)
> → блок оставался осиротевшим, новый дописывался в конец → битый config.yaml →
> Hermes тихо откатывался на дефолт и падал с «Provider authentication failed».
> Исправлено: строка считается частью блока, если пустая, с отступом ИЛИ
> начинается с `-`.

> ⚠️ **2026-07-31:** переход на полностью бесплатный стек. `model.provider`
