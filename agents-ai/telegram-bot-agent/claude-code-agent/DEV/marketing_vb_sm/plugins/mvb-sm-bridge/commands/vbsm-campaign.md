Ты — оркестратор смешанной маркетинг-системы **marketing_vb_sm** (команды Вадима × специалисты Сергея). Запусти полный цикл для: **$ARGUMENTS**

**Следуй скиллу `marketing-vb-sm`** — там фазы, владельцы шагов и правила приоритета. Главное правило: **исполнение отдаётся точкам входа Вадима, а не переписывается здесь.** Его система живёт (`/weekly-posts` уже deprecated, соцпосты идут из статьи), поэтому захардкоженная цепочка агентов гарантированно отстанет. Твоя работа — обвязка до и после.

1. Создай slug (kebab-case) и папку `.claude/scratchpad/<slug>/vbsm/` — **только для артефактов Сергея**. Артефакты Вадима остаются там, куда их кладут его пайплайны (`workspace/seo/articles/<slug>/`, `workspace/social/articles/<slug>/<profile>/`) — не переноси, их читают его агенты и его Telegram-бот.

2. **Стратегия (Sergiy).** Через Task tool вызови `marketing-strategist`. Он ОБЯЗАН сперва прочитать бренд-контекст Вадима: `CLAUDE.md`, `about-me.md`, `audience.md`, `brand-assets/` (включая `content-strategy/content-plan.md`, `social-profiles-config.md`, `linkedin-post-prompts.md`), прошлые посты/статьи, конкуренты. Только потом стратегия (слои L0–L8, приоритизация ICE). Пишет `strategy.md`, `plan.md`, `risks.md`.

3. **Гейт одобрения.** Остановись. Покажи план + допущения + предсказанные анти-паттерны. Жди явного `go` до любого производства, трат или outbound. У пайплайнов Вадима есть свои чекпоинты сверху — они не дублируют этот, не пропускай ни те, ни этот.

4. **Исполнение — вызывай ЕГО команды, не его агентов поштучно:**

   | Трек | Команда |
   |---|---|
   | Лонгформ / SEO-статья | `/new-article <тема\|slug> [stage]` |
   | Соцпосты из готовой статьи | `/post-from-article <article-slug>` — **только** когда `publish-package.md` статьи в статусе `approved_for_publish` |
   | Outbound-кампания | `/outbound [stage] [campaign-slug]` |
   | Квартальные темы контента | `/quarterly-review` |
   | QC одного артефакта | `/qc <path>` |
   | Paid | `paid-media-buyer` (сторона Сергея, своей команды у Вадима нет) |
   | Email / lifecycle / CRM | `lifecycle-marketer` (то же) |

   Нет команды под трек — спроси его `orchestrator`, он единая точка входа и знает, какой workflow и какие агенты соответствуют запросу. Его `context-pack-builder` запускается внутри его же workflow — не прогоняй заранее сам.

   Три вещи, которые нельзя обходить:
   - `seo-planner` Phase 0 сверяет статью с `content-plan.md`. Вернул `refresh` / `section-first` / `review-decide` / `lead-magnet` — это законный ответ: доложи и поправь `plan.md`. **Не** проталкивай новую статью. Нужна именно она — сперва добавь строку в `content-plan.md` вместе с Вадимом.
   - Соцлиния начинается с **одобренной статьи**, а не с идеи из брифа. `visual-brief` — только после того, как Вадим одобрил текст.
   - В outbound человеческие шаги (выгрузка Sales Navigator, запуск в closely.io) — это реальные шаги. Останавливайся и говори об этом, не имитируй.

5. **QC-гейт (оба мира).** Каждый ассет проходит бренд/факт-проверку Вадима — `mvb-social:brand-checker` на пост, `quality-controller` ≥ 12/20 — **И** `hermes-verify` (доказательство критериев из `plan.md`). Ничего не публикуется, пока оба не дали ОК. Балл ниже 12 — это стоп, а не замечание.

   ⚠️ `brand-checker` существует **дважды** и это разные агенты: `mvb-core:brand-checker` (аудит бренд-войса любого текста) и `mvb-social:brand-checker` (PASS/FAIL по посту, вызывается `post-drafter`). Всегда указывай неймспейс — без него ответит не тот.

6. **Измерение.** `marketing-analyst` (Sergiy) — атрибуция, воронка, CAC / LTV / ROAS против `plan.md`. `social-analytics` (Вадим) — паттерны органики по профилям. `campaign-analyzer` (Вадим) — learnings по outbound.

Приоритет при конфликте: **что делать и почему — решает Sergiy; на-бренд и правда ли — решает Vadim.** Сомнение про бренд/факт → Vadim. Сомнение про приоритет/бюджет → Sergiy. Полная таблица владения — в скилле.
