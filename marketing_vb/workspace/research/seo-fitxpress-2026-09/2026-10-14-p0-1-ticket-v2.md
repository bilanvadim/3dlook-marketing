# P0-1. Cookie-consent and GTM JS errors (site-wide), dead clicks on /pricing/

**Priority:** P0
**Pages:** https://3dlook.ai/pricing/ and https://3dlook.ai/contact-us/. The main fix is one plugin setting and fixes every page on the site.
**Monitoring:** Clarity data in the sheet "Q4. Tech SEO/GEO", tab "0.1": rows 31–39 (JS errors), rows 45–49 (recordings), rows 56–58 (UX).

## Why it matters

/contact-us/ holds the "Contact us & Partnership" form (`f227f5ce-8ce1-473d-a4f8-597c832979cc`), the main source of inbound deals. /pricing/ holds four demo and contact popups: FX Starter, FX Pro, FX Personalized and MT Enterprise.

## Root causes (reproduced 2026-10-14)

### 1. Cookie banner vs Flying Scripts: 446 of 519 errors (86%)

Errors:
- `Cannot read properties of undefined (reading '_lawSelected')` at `webtoffee-cookie-consent/lite/frontend/js/script.min.js?ver=3.5.5:1:108`
- `Cannot read properties of undefined (reading '_regions')` at `gcm.min.js?ver=3.5.5:1:96`
- The Safari versions of the same two errors (`undefined is not an object …`)

How it happens:
- The plugin is WebToffee GDPR Cookie Consent 3.5.5.
- **Flying Scripts** delays three of its scripts: the inline config (`_wccConfig`, `_wccGCMConfig`, loaded as a `data:` URI), `script.min.js` and `gcm.min.js`. WP Rocket "Delay JavaScript execution" is **off** on these pages.
- On the first interaction, or after 10 s, Flying Scripts sets `src` on all three at once. They run in whatever order they finish loading.
- When the plugin JS is cached and the visitor interacts within ~2 s of load, the two files run before the config and throw. This is the normal case when someone clicks through from the homepage.
- Reproduced 10/10 on desktop and 3/3 in mobile emulation (Chromium). It does not happen on a cold first visit.
- Effect: on that pageview the cookie banner and the "revisit consent" button don't render, so consent is not collected.

**Fix:** exclude the three WebToffee scripts from Flying Scripts: the `webtoffee-cookie-consent-js-extra` config, `script.min.js` and `gcm.min.js`. The fix applies to every page.

### 2. GTM tag "HubSpot chat tracker": 37 errors (7%)

- The tag is in GTM-PW77M7K, tag_id 179, and fires on All Pages.
- Its code is `if("https://app.hubspot.com"!==a.origin)return!1;a=JSON.parse(a.data);`, with no type check and no try/catch.
- When the message data is an object, it throws `JSON Parse error: Unexpected identifier "object"`.

**Fix:** `if (typeof a.data !== 'string') return; try { a = JSON.parse(a.data) } catch (e) { return }`. This is a GTM change, not a WordPress one.

### Checked and not the cause

- **Elementor:** these pages have no Elementor popups. The CTAs open remodal popups.
- **HubSpot forms:** they render in 117–191 ms on desktop and ~650 ms on the first mobile tap, with no errors.
- **jQuery:** the page loads one copy (3.6.0). Clearout injects a private 3.7.0 with `noConflict`, and it throws no errors.
- **Mobile-only or desktop-only mechanism:** none. The errors and their trigger are the same on both.

## Dead clicks on /pricing/ (desktop only)

Clicking these elements does nothing:
- the plan-name pills (`h3.title`)
- the "Recommended" band and the "save up to 20%" pill
- the price blocks and the feature rows
- the "FitXpress" switch when it is already active (UX row 58: users take it for a button)
- the header items with `href="#"`: Use Cases, Made-to-Measure, Resources, About 3DLOOK

Before fixing, confirm which elements get the most dead clicks: Clarity → Heatmaps → /pricing/ → Dead clicks, desktop.
- Plan cards and the switch are design questions. They go to Kristina, together with the pricing-page redesign (Doc of Oct 14).
- The header `href="#"` items go to dev: open the menu on click, or point them to a real URL.

## Also found (separate, quick fixes)

1. **Desktop:** the HubSpot chat welcome bubble (highest z-index) covers the cookie banner's "Accept All". A real click does not record consent. The same banner covers the first-screen "Book a demo" / "Talk to sales" on /pricing/.
2. **Mobile:** the cookie banner takes ~32% of the screen and sits over the popup form and the /contact-us/ submit button.
3. **Redirect:** `https://3dlook.ai/pricing` (no trailing slash) returns 301 to 3dlook.me, which then goes to the homepage (a Redirection plugin rule). The chatbot's "7-day trial" button links to `/pricing?utm_…`, so those visitors land on the homepage. Point the rule to `/pricing/`.
4. The MT Enterprise button says "Start a Trial" but opens a contact form.
5. ~~/pricing/ loads HubSpot `v2.js` 4 times and OptinMonster `api.min.js` twice.~~ **Withdrawn 2026-10-16.** The page has 4 `<script>` tags for `v2.js` and 2 (plus 2 inline injectors) for `api.min.js`, but the browser makes one request for each (Assel's DevTools screenshots, re-checked live in Playwright the same day). Nothing to fix.

## QA

1. **Reproduce before and after, with the DevTools console open.** Load the homepage, then click through to /pricing/ (or /contact-us/) and scroll or move the mouse within 1–2 s.
   - Before the fix: the `_lawSelected` / `_regions` errors appear and there is no cookie banner.
   - After the fix: no errors, and the banner renders.
   - A cold first visit does not reproduce the bug.
2. **Browsers:** desktop Chrome and a real iPhone in Safari. The Safari wording of both errors and the JSON error only show up in real Safari, and no WebKit test was run.
3. **Popups:** open each one (Starter, Pro, Personalized, MT Enterprise) and check that the form renders.
4. **Test submissions:** 5 forms × 2 devices = 10. These forms trigger HubSpot automation (owner assignment, auto-reply, a nurture sequence for pricing leads). So:
   - warn sales and #inbound-leads before testing
   - use one pattern for every test address: `qa+<form>-<date>@3dlook.me`
   - delete the test contacts afterwards
5. **GA4 DebugView:** `generate_lead` fires with the correct `form_name` for all 5 forms, and `demo_click` fires on the demo CTAs.
