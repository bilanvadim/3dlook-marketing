### H2.1 — The engagement problem in remote care programs
- Goal: Reader recognizes the specific engagement gap remote programs face — no in-person touchpoints, reliance on self-reported data, motivation drop-off, program abandonment.
- Word count target: 250–350
- Must-cover:
  - Remote-first programs lose the physical touchpoints (in-clinic weigh-ins, visible measurement) that used to anchor motivation.
  - Self-reported weight/BMI is inconsistent and easy to misremember or misstate; it gives programs a weak signal.
  - Motivation decays when progress is invisible; repeat check-ins become a churn risk instead of an engagement engine.
  - Set up the reframe: the question is not "how do we message patients more" but "what objective signal can patients and care teams both see between visits?"
- Keywords to weave: patient engagement telehealth body data, body scanning motivation adherence
- Sources: none external here (framing paragraph); draw pain framing from `audience.md` shared spine + Telehealth segment.
- Approved claims: none (problem statement, no product claims yet)
- Boundary: none touched yet. Do not imply a clinical or eligibility problem — this is an engagement/experience problem.

### H2.4 — The engagement mechanics of structured body data
- Goal: Explain *why* structured body data drives engagement — the core value section. Reader understands the behavioral mechanics.
- Word count target: 400–550
- Must-cover (each as a short labeled point, prose-led):
  - **Motivation** — visible change sustains effort where a flat weight number does not.
  - **Visual feedback** — a 3D model and body-composition outputs give patients something concrete to see.
  - **Progress understanding** — composition + 80+ measurements explain change that weight alone hides (e.g. lean mass vs fat mass shifts).
  - **Scan-to-scan comparison** — repeatable capture (`< 1 cm` repeatability) means small real changes are not lost in measurement noise.
  - **Goal setting + habit formation** — recurring scans create a rhythm and a shared reference point.
  - **Remote check-ins + reduced appointment friction** — asynchronous progress capture reduces the need for a synchronous visit just to record a measurement; **supports** (not replaces) the check-in.
