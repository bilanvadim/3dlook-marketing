## Issues, by priority

### P1. Hero videos are 6.6–10 MB, with no faststart and no poster
`assets/video/pricing/FitXpress.mp4` is 10.2 MB, `MT.mp4` 6.6 MB and `Wrist.mp4` 9.9 MB. Each is 1920×1080, 16 s at 3–5 Mbps, with an audio-free background loop. The same file goes to phones: a mobile load transferred about 10 MB. The `moov` atom sits at the end of each file, so the browser has to fetch the end before it can show the first frame. The video is the LCP element (2.4–2.7 s in the lab on a fast datacenter link; much slower on 4G). There is no `poster`.
Fix: re-encode with `-movflags +faststart`, add a WebP poster, and serve a smaller file below 680 px.
Test encode made on 2026-11-05 (visually identical, because the background is blurred):

| File | Now | 1280×720, CRF 28 | 854×480 (mobile), CRF 30 | Poster (WebP, frame at 1 s) |
|---|---|---|---|---|
| FitXpress.mp4 | 10.2 MB | 0.78 MB | 0.34 MB | 8 KB |
| MT.mp4 | 6.6 MB | 0.41 MB | 0.19 MB | 5 KB |
| Wrist.mp4 | 9.9 MB | 0.69 MB | 0.28 MB | 8 KB |

Command: `ffmpeg -i X.mp4 -vf scale=1280:-2 -c:v libx264 -crf 28 -preset slow -pix_fmt yuv420p -an -movflags +faststart X-720.mp4` (mobile: `scale=854:-2 -crf 30`). The files went to Asselya in Slack on 2026-11-05.

### P1. The homepage hero images are preloaded on /pricing/
In `<head>`: `<link rel="preload" as="image" fetchpriority="high">` for `2025/04/main-hero-{mobile,laptop,desktop}.webp` (105–150 KB each). The page never uses them, and Chrome warns "preloaded but not used". They compete with the real LCP. The preload has to be limited to the homepage (in the theme or the WP Rocket preload settings).

### P1. `pricing_plan_click` cannot tell plans apart and misses MT trials
The `plan` parameter is the Click Text, so Starter and Pro both send "Book a demo", and FX Personalized, MT Enterprise and Wrist all send "Talk to sales". The trigger regex (`book a demo|let's talk|request a demo|talk to sales|sign up`) does not match "Start a 7-day trial", so clicks on the MT Basic and Premium buttons send no GA4 event at all (verified: zero events on click).
All seven buttons already have a distinct `data-event-name` ("Starter plan click", "Pro plan click", "Personalized plan click", "Basic plan click", "Premium plan click", "Enterprise plan click", "Wrist plan click"). Fix in GTM: trigger on clicks where the element or its closest `a` has `data-event-name`, and set `plan` from that attribute (Custom JS variable: `{{Click Element}}.closest('[data-event-name]').getAttribute('data-event-name')`).

### P1. GA4 `form_start` fires 4–5 times on every page view
On load GA4 Enhanced Measurement sends `form_start` for every hidden HubSpot form, with `first_field_name=landing_page_first`, `first_field_type=hidden`. The script that fills `landing_page_first` triggers it, and no visitor touches the forms. As a result `form_start` on /pricing/ is meaningless, and probably on every page with a HubSpot form too. Fix: turn off "Form interactions" in GA4 Enhanced Measurement. `generate_lead` from `hs_form_submit` already counts submissions. The other option is to fill the field without dispatching input/change events, if HubSpot still picks up the value that way.

### P2. The Wrist form is missing from the GTM `form_name` map
`4019c559-5136-4de8-bf5b-dda2de8807fb` is not mapped, so a Wrist lead arrives as `generate_lead` with `form_name=other`. Add `wrist_pricing` (or `wrist_demo`). While editing, rename `0a22d79d…` from `pricing_enterprise` to `mt_pricing_enterprise`, because it is the MT form.

### P2. The MT form has fewer attribution hidden fields
`0a22d79d…` has the UTMs and `landing_page_first` but lacks `initial_referring_domain_`, `search_engine` and `distinct_id`, which the other four have. Add them in the HubSpot form editor.

### P2. The MT trial button lands on a page that answers HTTP 404
`https://mtm.3dlook.me/accounts/signup` renders the sign-up form but returns status 404. It was found in the 10-14 browser audit (`research/seo-fitxpress-2026-09/data/2026-10-14-p0-1-browser-audit.md`), but it never made it into the P0-1 ticket sent to devs (Asselya caught this 11-06). Dev ticket: `ticket-mt-signup-404.md`. Link checkers, ad-policy crawlers and uptime checks treat it as broken. This needs the MT product team.

### P3. Small items

- No internal link points to `/pricing/?wrist`. `/wrist-measurement/` links only to `/pricing/` and `/pricing/?mt` (the header). Add a "See pricing" link to `?wrist` on the wrist page.
- The `?product=` deep links from the 10-14 prototype are not supported; only `?mt`, `?wrist` and `?fitxpress` work. Nothing links to `?product=` today.
- The alt text of the three FX modal images ends with "…in 2025 Home." (copied from the homepage).
- The 10 award logos in "Recognized by…" have `alt=""`. That is acceptable because the text sits next to them. The block itself is fashion-era (Gartner Retail 2021, Digiday in-store, LVMH 2019, "Top fashion tech startups"), which is a content decision.
- Apollo's intent pixel (`aplo-evnt.com … app_id=663a0714…`) answers 400 on every click. Check the Apollo tracker settings.
- The legacy Universal Analytics tag (`UA-92309701-1`, `analytics.js`) still fires from GTM to a property that stopped processing in July 2024. Remove it.
- Sitewide, not page-specific: the old header still has 4 `href="#"` items (the new navigation approved 10-22 is not shipped). On mobile the EU cookie banner covers about 40% of the screen and overlaps the plan modal, and the HubSpot chat bubble sits on "Reject All".
- Sitewide consent (known since 10-23): with consent "no", GA4, Google Ads (AW-842555409), the Meta pixel script, Clarity, Hotjar and Apollo still load. This is a legal and DPO decision, not part of the page release.
