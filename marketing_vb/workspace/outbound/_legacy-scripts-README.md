# `_legacy-scripts/` внутри папок кампаний — что это и почему не переиспользовать

Собрано 2026-09-02. В шести кампаниях лежало **26 одноразовых скриптов** (660 КБ), которые
агенты писали прямо в папку данных. Они перенесены в `_legacy-scripts/` внутри своей
кампании — не удалены, потому что это запись о том, как получились артефакты, которые уже
ушли клиентам.

| Кампания | Файлов |
|---|---|
| `2026-07-16-au-telehealth` | 9 |
| `2026-07-27-australia-telehealth` | 6 |
| `2026-07-23-israel-telehealth` | 4 |
| `2026-07-31-uk-telehealth-digital-health` | 10 (включая `.sh`, `.js` и черновой текст) |
| `2026-08-07-us-digital-fitness` | 3 |
| `2026-07-21-eu-telehealth-weightloss` | 1 |

## Почему они появились

`people-extractor.md` и `closelyhq-importer.md` до 2026-09-02 давали агенту шаблон на
pandas. **pandas не установлен ни в системном python3, ни в venv Хермеса** — шаблон не
запускался никогда, поэтому каждый прогон писал свою замену с нуля.

## Почему их нельзя брать за образец

1. **Они разошлись между собой.** Шесть `gen_batch*.py` в AU-кампании имеют шесть разных
   md5 при одинаковом размере 54 367 байт. В докстринге `gen_batch1.py` написано
   «Generate 50 … for **batch_3.csv**», а код читает `batch_1.csv` — копипаст, который
   никто не поправил.
2. **Они генерируют обсолетный формат.** Все они пишут 4-шаговую последовательность с
   текстовой ноткой к запросу в друзья. С 2026-08 схема — 2 сообщения, инвайт **без**
   нотки, лимиты 600 / 550 символов. У AU-кампании 253 из 253 сообщений не проходят
   нынешний гейт: медиана Step2 — 902 символа, em dash в 253 из 253.
3. **Один из них — причина семинедельного простоя.** `icp_validate.py` записал
   `people-validated.csv` без колонок `first_name` / `last_name` / `person_linkedin_url`,
   импортёру нечего было мапить, и `closelyhq-import.csv` вышел на 253 строки с пустой
   идентификацией. Ассерт импортёра проверял наличие колонки, а не её непустоту, и молча
   прошёл.

## Что использовать вместо

```bash
P=/home/vadim_prod/3dlook-marketing/marketing_vb/scripts
python3 $P/outbound-pipeline.py extract-people   --campaign X --dry-run
python3 $P/outbound-pipeline.py check-import     --campaign X
python3 $P/outbound-pipeline.py check-responses  --campaign X
python3 $P/outbound-pipeline.py fix-validated    --campaign X   # вернуть identity из people-raw
```

Всё на stdlib, у каждой команды exit code, механика описана в шапке
`scripts/outbound-pipeline.py`.

**Правило:** папка кампании держит данные, а не код. Нужен новый шаг — он идёт в
`scripts/` как подкоманда с тестом на реальных данных, а не в папку кампании как
`generate_v3.py`.
