## How agents use this file

Before any new FitXpress article, `seo-planner` (Phase 0) and `context-pack-builder` (track=seo) **must locate the topic's row here** and carry these fields downstream:

- **Main hub topic** — the authority page this piece belongs under (every supporting article links up to it).
- **Cluster section** — the narrow slot inside the hub.
- **Intent** — Hub / TOFU / MOFU / BOFU / GEO-comparison / listicle / objection handling / conversion → sets depth and CTA. (The sheet's «Intents system» tab lists the ~30 combined values it uses.)
- **Action Type** — the writing instruction (see legend). **This is a gate**, not a suggestion.
- **Execution Priority** — P0 (backbone) · P1 (strong supporting) · P2 (conditional: validate demand or start as a hub section) · `P0/P1 - published` (live; maintain, don't recreate).
- **URL of already published articles** — refresh target, internal-link source, or cannibalization warning.
- **Recommendation** — the specific angle/decision for this row.
- **Cannibalization Guardrail** — hard boundary; a new page must not duplicate what already owns the intent.

**A title without its strategy row is not a brief.** If the topic is not in this plan, `seo-planner` stops and asks Vadim to place it (hub + cluster + action type) before proceeding.

## Action Type legend (treat as a writing instruction)

The sheet writes free-form variants. **Gate on the family (how the value starts), then read the qualifier after `/`, `:` or `;` as the rule for that row.** A qualifier containing *if / only if / unless* makes any create conditional.

| Family — the value starts with… | Gate | What the agent does |
|---|---|---|
| **Published / …** · **Published supporting article / …** · **Published listicle / …** · **Existing hub / …** | **STOP — already live** | No new page. *maintain hub* = the hub stays the anchor, supporting pieces link up. *monitor + interlink* = add links in and out, watch performance before writing adjacent content. *canonical … asset / FAQ / expansion* = the page every vertical links to for that topic. *supporting set reconsidered* = the hub absorbed several planned pieces, see the rows below it. *Existing hub / refresh if insurance becomes priority* = refresh only on Vadim's call. |
| **Create net-new** · **Create net-new supporting article** · **Net-new supporting article** · **Net-new listicle** · **Create net-new … sub-hub** · **Publish planned hub** | **GO → Phase 1** | Write it — only if no existing page owns the intent (check the URL column). A narrowing qualifier is part of the brief: *but narrower than originally planned* = go deeper than the hub on one angle. |
| **Create net-new … if <condition>** · **Net-new supporting article or FAQ expansion** | **ASK** | Conditional create. Proceed only when Vadim confirms the condition (e.g. "patient-centric DCT messaging matters"); otherwise recommend the section/FAQ form. |
| **Create if validated …** · **Create only if validated …** | **STOP — review** | Same as Review / decide: recommend with evidence (search demand, campaign, sales need). |
| **Review / decide …** | **STOP** | Recommend: new article / hub section / product-page section / lead magnet / defer. The qualifier is the decision rule (e.g. *create one shared comparison page, not two duplicates*; *create only if narrower than telehealth hub and BOFU page*). |
| **Section-first …** · **Section first …** · **Merge / section-first …** | **STOP** | Recommend a section or FAQ inside the named hub. *link to central FAQ* = privacy rows: a short vertical note plus a link to the trust FAQ, never a restatement of storage/retention/deletion/HIPAA/GDPR/CCPA/SOC 2/FDA answers. Standalone only when the stated condition is met and Vadim confirms. |
| **Refresh / expand …** · **Refresh / link to …** | **STOP** | **Do NOT draft new.** Improve the existing page named in the URL column (sections, FAQs, internal links, current positioning). |
| **Lead magnet / sales asset** · **Lead magnet / downloadable checklist** | **FORMAT** | Checklist / PDF / embedded CTA / buyer guide. Never a thin indexed post unless Vadim approves expanding it into a full guide. |
